개정 2026-11-27 (회차 93, Claude) · 기준 버전 0.62 · 코드 구조·기술 규칙·배포·시험 체계

- 기획서(`docs/DESIGN.md`)가 무엇을 만드는가의 기준, 이 문서는 어떻게 만드는가의 기준.

## 1. 기술 기반

- 웹 기술(HTML·JavaScript·캔버스 2D), 게임 엔진·외부 라이브러리 미사용 (필요 시 목적·대안 제시 후 사용자 승인)
- 실행 환경: 모바일 웹 브라우저 (기준 삼성 인터넷·크롬)
- 게임 루프: 입력 → 상태 갱신 → 충돌 판정 → 그리기, 경과 시간 기반 갱신
- 프레임: 기본 60 (120Hz 화면은 2프레임에 1번 갱신), 설정 120 시 주사율 그대로

## 2. 코드 구조

### 원본과 결합

- 원본 `src/*.js` → `sh build.sh` → 단일 `index.html` (결합본, 약 3.8MB, 그림 데이터 포함)
- 결합 순서는 `build.sh`가 기준. 뒤에 오는 파일이 앞 파일의 함수를 감싸거나 덮어씀
- 그림 묶음: `dev/pack-*.cjs`가 `assets/`의 그림을 `src/*-data.js`로 내장 (build.sh 안에서 실행)

### 작성 규칙

- 설정표: 조정 대상 수치는 설정표(config.js 또는 해당 모듈 상단 상수)에 모음, 본문 숫자 직접 기입 지양
- 데이터 목록: 무기·보조 효과·분기·직업·적·페이즈·보스·기록 조각은 목록 형식, 신규 콘텐츠는 목록 추가로 등장
- 명명: 코드 식별명 영문, 화면 문구는 표시 명칭으로 분리 (현재 코드의 job·sym·base 식별명은 '인물·전용 무기' 용어 전환 후에도 당분간 유지)
- 변경 원칙: 변경 부분만 수정 우선, 전체 재작성은 구조 변경 시에만
- 그림 미로딩 시 기존 그리기로 대체되는 구조 유지, 기존 그림 파일 이름 변경 금지
- 마왕 피해 보정(dmAdjust)은 모든 피해 배율 적용 뒤 마지막에 호출
- 선택지 후보를 가중치로 뽑는 구조에서 항목 수를 늘릴 때 후보군 총 비중 정규화 함께 적용
- ★확인 기록(회차 95): 구현·기획안 완료 보고와 커밋 메시지 본문에 근거 1줄 — `확인: <문서·장>, 원칙 '<이름>'` (예: `확인: necromancer.md 3·5장, DESIGN 4장, 원칙 '플레이어 선택권'`), 근거 없이 Claude가 정한 부분은 '가안'으로 표기해 characters 5장 구현 메모에 기록

## 3. 성능 기준

- 목표: 적 동시 300~500, 60 FPS
- 기준 기기: 갤럭시 S23, 폴드8 (폴드8 발열은 0.48 이후 감소 확인)

- DEV 패널: 평균·하위 1%·하위 5% FPS 표시
