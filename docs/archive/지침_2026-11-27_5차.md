게임 제작 프로젝트 지침
개정일 2026-11-25 (5차)

[프로젝트 개요]
• 프로젝트명: '회귀의 들판' (모바일 세로형 탑다운 액션 웹 게임)
• 목적: 확정 기획에 따라 게임 완성 및 웹 배포
• 기간: 기한 없음, 완성도 우선
• 착수일: 2026-10-24 (1일차 기준)
• 제작 단계: 최소 플레이 버전 → 핵심 시스템 → 콘텐츠 확장 → 서사·메뉴 → 표현·보강 → 대규모 재구성 → 마감
• 대규모 재구성: 인물 재구성 회의(1페이지) → 연성 재설계(2페이지) → 문서 반영 → 인물 1~2명씩 분할 구현·가상 시험 → 대규모 밸런스(시험 결과 기준) → 실기기 시험
• 마감: 최종 수치 미세 조정, 참고 지표 확정, 중저가 기종 측정·최적화, 실기기 전체 점검·버그 일괄 수정, 문서 최종 정리, 재제작 교훈 정리, 최종 배포
• 종료 조건: 마감 단계 완료 및 최종 웹 배포

[게임 구조 원칙]
• 3층 구조: 무기 / 인물 / 성장
• 무기: 공용, 어느 인물이 골라도 동작·수치 동일, 인물이 무기 자체를 바꾸는 특혜 금지
• 인물: 전용 무기 1개 + 고유 규칙 + 궁극기, 인물 효과는 무기 자체의 동작·수치를 바꾸지 않음, 고유 규칙은 연성형(전용·연성 무기에만)이 기본이고 컨셉에 따라 전체형·대상형·주변형·자신형·제약형 허용, 제약형은 불쾌·불편 금지
• 성장: 전용 무기 = 발현(Lv 3) → 무기 각성(Lv 5), 일반 무기 = Lv 5 연성(짝 무기 Lv 5), 인물 쪽 = 인물 선택 후 돌발 사건 클리어 시 인물 각성
• 인물형: 기존 직업 전직을 인물 전환으로 변경, 표기는 '이름 · 부제(직업)', 이름·서사 컨셉은 추후 확정
• 인물 간 중복 금지: 같은 계열 인물도 플레이 감각이 확실히 달라야 함
• 용어: 인물별 무기는 '전용 무기'로 통일

[점검 의무]
• 게임·제작 방식·문서·코드·기획 어디서든 문제 또는 더 나은 방식이 보이면 요청이 없어도 먼저 지적
• 지금은 괜찮아도 이후 작업을 어렵게 만드는 것까지 포함
• 예시(한정 아님): 토큰 낭비, 문서 분산, 확장을 막는 구조, 원칙과 충돌하는 제안, 체감상 어색한 기획
• 방식: 응답 안에서 짧게 지적 + 대안, 결정은 사용자
• 치명적 문제(데이터 손실·배포 오류·되돌리기 어려운 결정 등)는 다른 작업보다 먼저 보고
• 정기 점검: 새 대화 시작 시 회차 번호가 5의 배수이거나 직전 회차에서 제작 단계가 끝났으면 시작 보고에 포함, 지침·문서·코드 구조 전체 점검 후 짧은 목록으로 보고

[GPT 아트 운영]

• 요청은 패치마다 전달하지 않고 누적, 사용자 요청 시 일괄 제공
• 일괄 제공 시 작업 단위별 텍스트 파일 여러 개로 분할 (GPT 새 대화 1회 처리 분량 기준)
• 요청문 포함 사항: 적용 위치, 배포 규칙, 동작 기술(자연스럽고 몰입감 있는 동작, 인물 정체성 강조), 작업 순서(그림 제작 → 그림 파일 GitHub 선 업로드 → 코드 적용·배포), 분량 과다 시 끊어 저장하고 HANDOFF에 진행 상황 기록
• 제공 완료분은 완료 표기, GPT 작업 후 Claude는 HANDOFF 기준으로 이어서 작업, 동시 작업 금지
• 임시 도형은 최종본 아님 표기, 색만 바꾼 구분 금지 (동작 자체 차별화)

• "실행" 1회로 구현 → 가상 시험 → GitHub 저장 → 배포 일괄 진행, 단계별 추가 확인 불요
• 중단 기준: 진행 불가 또는 구조 판단이 필요한 오류 발생 시에만 중단 후 질의

• 별도 지시 필요: 범위 밖 변경, 지침·DESIGN.md·DEV_SPEC.md의 확정 사항 변경
• 지시 불요: HANDOFF·현황판·메모리 갱신, 회의 기록(REWORK_MEETING.md·FUSION_GUIDE.md), 시험 기록 저장

• 취향이 갈리는 항목은 설정 옵션 우선 검토, 부담 큰 항목은 기본값 고정
• GitHub 쓰기 권한·배포 차단 시 Claude가 우선 해결, 불가 시 첫 응답에서 즉시 보고하고 그 회차는 회의만 진행
• 사용자 수정 요청 양식: "현상 / 원하는 결과" 2줄, 오류 시 화면 캡처 (실기기 버그 일괄 보고 가능)

[가상 시험]
• "N판 테스트" 입력 시 실행·판독·보고 일괄
• 수정 중: 10판 약식
• 묶음 완료 시: 일반 30판(인물 균등) + 무적 8판(판 길이) + 사용성 점검(화면·선택지·버튼 흐름) + 변경 기능 집중 점검, 연성 전수는 연성 관련 변경 시에만
• 합격 기준: 오류 0건 (사용성 점검 불통과 포함)
• 참고 지표: 판 길이, 보스전 시간, 돌파 횟수, 연성 도달 횟수, 최고 피해 무기 분산도, 인물별 돌파율
• 기록: 버전별 dev/sim_log
• 수정 우선순위: 오류 → 진행 흐름 → 피해 쏠림 → 자동 로직 자연스러움
• 한계: 자동 플레이는 체감·재미 판단 불가, 체감 항목은 사용자 실기기 시험으로 판단

[회차 운영]
• 회차 = 대화창 1개, 유형: 제작(작업 묶음), 회의(결정 안건, 코드 변경 없음), 문서(문서 일괄 갱신)
• 시작: "이어서 진행" 입력 시 직전 대화 마지막 내용 → HANDOFF 순으로 확인, 불일치 시 최신 기준 적용 후 보고, 확인 불가 시에만 사용자에게 요청
• 시작 보고: 일차, 단계, 이번 회차 작업, 이월분, 미해결 오류, 외부 대기, 쓰기 권한 상태, (해당 시) 정기 점검
• 제작 단계 착수 회차는 해당 단계 결정 안건 먼저 제시
• 전환 시점: 응답 왕복 15회 도달 시 안내·20회 이전 전환, 코드 전체 재작성 2회, 가상 시험 3회 이상 연속, 제작 단계 종료, 품질 저하 징후(이전 내용 재확인 증가·동일 오류 반복)
• 전환 시점 도달 시 다음 응답 첫머리에서 새 대화 전환을 먼저 안내
• 종료: 인계 요약 출력, HANDOFF 상태판 갱신·이력 3~5줄, 현황판 갱신, 메모리 갱신, 회의 회차는 회의 기록 저장, 개선 기록(해당 시 1~2줄)
• 인계 요약 항목: 단계, 완료 작업, 코드 최신본·정상 버전, 최근 시험 결과, 다음 작업, 미해결 오류, 미결·보류, 외부 대기
• 2주 이상 공백 후 재개 회차: 현황 복기 + 소형 작업만 배치, 중단 원인 1줄 기록
