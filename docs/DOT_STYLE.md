# 도트 그림 규칙 (회차 99 신설, Claude 작성)

모든 도트 그림(인물·몬스터·보스·배경·이펙트·초상화)의 일관성 기준. Claude가 도트를 찍을 때와 GPT 원본을 받을 때 모두 이 문서를 따름.
칸 수(그림 크기)는 시야 결정에 따라 바뀔 수 있음 → 3장 표만 고치면 됨.

## 1. 기본

- 시점: 정면에서 살짝 위에서 내려다본 2D 탑다운 (머리·몸 앞면이 함께 보임)
- 칸 크기 통일: 한 화면 안의 모든 그림은 같은 칸 크기. 확대는 정수배(2배·3배)만, 1.5배 같은 비정수 확대·회전 금지
- 빛 방향: 왼쪽 위 고정 (밝은 면 = 왼쪽·위, 그림자 = 오른쪽·아래)
- 금지: 반투명, 그라데이션, 흐림, 안티에일리어싱(경계를 흐리게 하는 중간색 점)

## 2. 선과 색

- 외곽선: 바깥 1칸, 순수 검정 금지 → 그 물체의 가장 짙은 색(인물은 보조색 계열)
  - 빛 받는 쪽 외곽선은 한 단계 밝게 해도 됨 (선택적 외곽선)
- 명암: 재질마다 3단계 (그림자·기본·밝은 면), 가장 밝은 점(하이라이트)은 금속·눈·보석에만
- 색 수: 인물 16색 이내, 잡몹 12색 이내, 수문장 24색 이내(회차 101), 배경 조각 8색 이내
- 인물 색: DESIGN 10장 3색(주색 넓게 / 보조색 테두리·그림자 / 포인트색 작게) 그대로
- 망토: 인물 색 계열로 인물마다 다르게 (흰 형체만 진홍 #9E1B32), 찢긴 모양 금지
- 자홍(분홍 보라) 금지: 적 공격 예고 전용
- 화면 층: 배경 = 가장 어둡고 채도 낮음·외곽선 없음 / 적 = 중간 채도·어두운 외곽선 / 플레이어·이펙트 = 가장 선명

## 3. 크기 (칸 수)

- 회차 99 결정: 화면 시야 1.2배 넓게 + 모든 그림 칸 수 1.25배 (미리보기 체감 확인 후 확정)
- ★기준 기기 = 일반 바 형태 휴대폰(S23, 화면 폭 360점·배율 3). 실제 보이는 폭은 config viewWidth(400, 시뮬레이션용)가 아니라 input.js battleZoom(폭 ÷ 390 × 1.4, 1.15~2.05)이 정함 → S23 기준 지금 약 280, 1.2배 = 약 335 (battleZoom 계수 1.4 → 약 1.17로 조정 예정)
- 칸 수는 그 크기 그대로 찍는 것이라 확대가 아님 → 1.25배여도 칸이 뭉개지지 않음
- 칸 수는 짝수로 맞춤 (가운데 정렬·좌우 반전 시 한 칸 어긋남 방지)

- ★회차 100 변경: 인물 40칸 → 64칸(표 전체 1.6배). 게임 안 크기는 그대로(인물 = 게임 좌표 40), 1칸 = 게임 좌표 0.625, S23·시야 1.2배 기준 1칸 약 2픽셀
  - 이유: Claude가 40칸으로 다시 찍은 1차본이 원본 형태를 잃음(사용자 평가 매우 나쁨), GPT 원본을 64칸으로 줄이면 같은 화면 크기에서 원본 품질 유지
- 화면 폭 대비 인물(게임 좌표 40): 약 40/335 ≈ 12% / 폴드 펼친 화면은 확대 상한(2.05) 때문에 더 넓게 보임

## 4. 형태

- 인물 비율: 약 2.5등신, 머리 = 몸 높이의 약 40% (작은 화면에서 표정·머리 모양이 보이도록)
- 발 위치: 그림 아래쪽에서 2칸 위에 고정 (그림자 자리), 좌우 중심은 그림 가운데
- 실루엣: 검은색으로 채워도 누구인지 알아볼 수 있어야 함 (머리 모양·무기·망토로 구분)
- ★가장자리 여백(회차 104): 그림이 캔버스 끝에 닿지 않게 사방 2칸 이상 (바르간·이그나 공격 장면이 오른쪽 끝에서 잘린 사례)
- 고아 점 금지: 혼자 떨어진 1칸짜리 점은 지우거나 이어 붙임
- 곡선 계단: 1-1-2-3처럼 길이가 고르게 변해야 함, 1-3-1-2처럼 들쭉날쭉 금지
- ★얼굴 공통 규칙(회차 101): 정면 양쪽 눈 같은 높이·좌우 대칭, 눈은 뜬 상태(흰자·눈동자 모두 보임, 눈꺼풀이 눈동자를 덮지 않음), 한쪽 눈꼬리만 올리거나 내리기 금지(사선 눈), 입은 다문 짧은 선(벌린 입·이빨은 인물 설명에 있을 때만), 표정은 눈썹 모양으로, 턱선 1칸 그림자로 얼굴이 둥글게 퍼지지 않게
  - 근거: D02T 도적(눈 높이 1칸 차이·반쯤 감긴 눈·벌린 입 → 멍한 인상), D01T-3 광전사(감긴 눈·벌린 입) 사례

## 5. 움직임

- 방향: 4방향 (아래·위·옆 3세트 + 옆은 좌우 반전), 대각선은 나중
- ★적 방향(회차 101 Claude 결정): 잡몹·정예·수문장은 오른쪽 옆모습만(왼쪽 = 좌우 반전, 위·아래 그림 없음), 이동 4장 + 특수 행동 장면 / 이유: 적은 수가 많고 크기가 작아 방향 구분보다 종 구분이 중요, 작업량 절감
- 서 있기 2장: 몸 전체가 1칸 오르내림 (숨쉬기)
- 걷기 4장: 발 닿음 → 지나감 → 반대발 닿음 → 지나감, 프레임마다 실루엣 크기 거의 일정
- 맞음: 그림 없음, 코드로 번쩍임·밀림
- 공격 자세 2~3장 / 궁극기 1~2장 / 사망 3~4장 / 인물 특수 동작 (GPT_REQUESTS 도트 전환 장)
- ★인물 동작 방향(회차 104 Claude 결정 가안): 공격 = 오른쪽 옆 3장(준비 → 휘두름·발사 → 마무리) / 궁극기 = 정면 2장 / 사망 = 정면 4장 / 특수 동작은 인물별 / 이펙트는 코드가 그림, 도트는 몸·무기 동작만
- ★정예·우두머리 표시(회차 104): 정예 = 금빛 장식 1개(왕관 금지), 우두머리 = 금관, 금빛 테두리 빛은 코드
- 망토는 이동 방향 반대쪽으로 1~2칸 늦게 따라옴

## 6. 제작 방식 (회차 100)

- ★회차 100 확정: GPT가 64칸 도트를 직접 찍음(원본 설정화 → 64×64 투명 PNG, 동작 프레임 포함), Claude = 검수(크기·색 수·발 위치·프레임 흔들림) + 게임 적용
  - 근거: 같은 게임 크기 비교에서 GPT 직접 64칸 > Claude 축소 64칸 > 테라리아풍 40칸(Claude) 순으로 깔끔함 (사용자 선택 1번)
- 원화 생략(회차 100 사용자 결정): 다음 인물부터 GPT가 처음부터 64칸 도트로 찍음, 서 있기 3방향이 설정화 역할 / 160칸 초상화만 따로 큰 그림 필요 / 화풍 기준 = assets/dot-src/berserker/gpt_dot/
- 요청문 공통 필수 문구: 작업이 끝나면 대화창에 미리보기 이미지를 직접 띄워 보여 줄 것(파일 이름만 알리는 것 금지), 수정 요청이면 전·후 비교 이미지 포함 (회차 100 사용자 지시)
- 발바닥 줄 = 맨 아래에서 3칸 위(0부터 세면 60번 줄), 인물 키 60칸 (도적 D02T 기준)
- 예비: Claude 축소 방식(dev/dot/d64.py: 면적 평균 축소 → 원본 팔레트 색으로 맞춤 → 외딴 점 제거 → 바깥 외곽선 1칸)
- 요청문 작성 시 주의: 무기 길이·폭 비율, 얼굴(눈·눈썹) 노출 같은 인물 정체성 요소를 수치로 명시 (D01T에서 대검이 짧게, 눈이 가려지게 나옴)
- Claude가 처음부터 손으로 찍는 방식은 쓰지 않음 (회차 100 실패 사례)
- ★요청문 템플릿(회차 101): gpt_requests/TEMPLATE_도트요청문.txt — 새 요청문·수정 요청문은 이 틀로 작성
- ★요청문 필수 '인상' 항목(회차 101 사용자 지시): 규격 외에 인상 한 줄, 성별·나이, 체형·자세, 머리·얼굴(눈·눈썹·입), 옷·망토, 무기·소품, 색, 피할 것을 구체적으로 — 전형적인 모습(예: 엔지니어 = 듬직한 체격·구레나룻부터 입 주변까지 덮은 갈색 수염)으로 / 기준은 8장

## 7. 파일

- PNG, 투명 배경, 칸 1개 = 픽셀 1개 (확대하지 않은 원본으로 저장)
- 이름: <대상>_<동작>_<방향>_<번호>.png (예: berserker_walk_down_1.png), 확인용 확대본은 _preview 붙임
- GPT 원본: assets/dot-src/<대상>/ (가로 약 512, 0.5MB 이하) / 완성 도트: assets/dot/<대상>/
